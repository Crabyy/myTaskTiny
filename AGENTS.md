# Project working agreements

- Complete authorized work and verification before reporting the result and the user’s next steps.
- Summarize changes and obtain the owner’s approval before committing, pushing, or publishing a release.
- Write documentation in clear, professional language. Use concrete behavior, concise instructions, and accurate release notes. Avoid hype, filler, and repetitive phrasing.
- Keep default shortcuts available through Restore defaults; customized keys replace the corresponding defaults.
- Preserve user recordings and settings during development and cleanup. Remove only identified generated artifacts.
